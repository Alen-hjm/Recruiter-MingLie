# 明猎界面设计约定

明猎以「说出需求 → 助手执行 → 查看人选」为主线。桌面工作台承担完整任务，浏览器侧栏承担随手提问和当前简历分析，两者共享视觉语言。

## 参考与取舍

| 来源 | 借鉴重点 | 在明猎中的应用 |
| --- | --- | --- |
| [MotionSites](https://motionsites.ai/) | 首屏构图、字体层级、视觉焦点 | 紧凑的品牌区域，以需求输入区为主要操作入口 |
| [React Bits](https://reactbits.dev/) | 局部强调、短促入场、悬停反馈 | 示例提示依次出现，候选人悬停时强化边界 |
| [Uiverse](https://uiverse.io/) | 输入、按钮、选择器的状态细节 | 可识别的岗位选择、输入焦点、发送按压反馈 |
| [Anime.js](https://animejs.com/) | 时间编排、缓动和顺序反馈 | 提示项短间隔入场，任务阶段随实际状态变化 |
| [Aceternity UI](https://ui.aceternity.com/components) | 导航过渡、步骤强调、交互层次 | 导航背景滑移、执行阶段强调与聚焦输入边界 |

其中 React Bits 的 SpotlightCard、StarBorder 已实际取用源码并移植到工作台与扩展，其余网站仍属于设计参考。组件来源、固定版本、改造范围和许可证见 [组件来源与维护](ui-components.md)。实现使用原生 CSS / JavaScript，没有新增 React 等运行时依赖。

## 层级与密度

- 中性浅底承载信息，灰紫用于当前岗位和主操作，绿色仅表达已连接或已完成。
- 用户输入比示例提示更深、更大；辅助说明不与任务内容争夺注意力。
- 主屏保留一个明确主操作。低频操作收进菜单，参数配置放进设置。
- 侧栏保持阅读留白，不以装饰图标、卡片或说明文字填满空间。

## 动效边界

- 常规反馈约 160–200 ms，导航和局部入场约 280–400 ms；内容立即可操作，不等待退场动画。
- 示例出现时依次进入，用户输入后立即隐藏，避免挡住文字。
- 执行阶段来自服务端；只有任务运行中的当前阶段持续强调，结束后停止。
- 尊重系统「减少动态效果」偏好；侧栏隐藏时暂停 CSS 动画。
- 新效果优先使用 opacity / transform；不增加常驻指针循环或全屏装饰动画。
