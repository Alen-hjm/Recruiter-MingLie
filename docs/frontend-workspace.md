# 明猎前端工作台

面向猎头和招聘顾问，以“一句话 → 助手自动搜寻 → 分析 → 推荐”为主流程。首页是招聘助手，白色承载阅读，浅蓝、紫色与少量暖色呈现工作状态。标志由两个简历/岗位卡片轮廓和连接线组成，表达人才与机会的匹配。概览、项目、候选人、面试与报告承担成果查看与后续跟进。

## 日常操作

- 面向电脑端使用，侧边导航支持收起；`Ctrl / Cmd + K` 可按页面或岗位名称跳转。
- 输入明确的岗位与城市，如“找深圳半导体销售总监，10份”，助手调用完整招聘工具，建立岗位、启动现有自动化采集服务、分析并整理人选。必要条件不足才追问，不把实际执行变成手动填表。
- 对话与阶段进展同页展示，人选卡带匹配摘要和项目入口；阶段点亮依据服务端执行事件，不用定时器伪造进展。聊天也不会被显示成已经完成全部搜寻。
- 项目卡、概览和快捷导航中的岗位入口可交给助手继续。助手和搜索草稿、常用筛选按登录账号保存在当前浏览器会话内。模型密钥不进入浏览器状态缓存。
- 后台回合支持切页后恢复，同账号执行中禁止重复提交与清空。当前对话与回合登记采用单进程内存，服务重启会丢失，多 worker 不共享；岗位、简历和业务任务保存在数据库。采集等待超过30分钟或分析等待超过5分钟时，本轮提示后台任务仍在进行，完成后需要让助手继续；平台验证则提示处理并保留结果。
- 人才搜索只展示岗位、关键词、当前城市与目标份数。翻页上限在内部控制；实际获取数量仍取决于搜索结果和任务执行情况。恢复任务时只补充尚缺的份数。
- 未配置模型时，自动分析选项不可用；未分析的人选展示“未分析”，进入待核实组。
- 决策报告展示人选摘要、建议和可展开的匹配依据，完整原始报告保留在折叠区域，可导出为文本。没有附结构化证据时明确提示核实，不补造依据。
- 面试页区分约面记录与反馈。通过、待定、未通过会更新现有招聘进展，不把“待定”当作淘汰；“今日加入”统计记录创建日期，不代表具体面试日程。

## 新用户与项目概览

首次进入工作台自动展示四步开始指南：认识助手、配置模型、准备平台登录、填写第一条需求。可跳过，右上角“开始指南”可重新打开。引导进度按账号存入 SQLite，服务重启及重新登录后保留；引导结束不等同于模型接入或平台登录成功。引导中前往设置、搜寻详情后可重新打开接续步骤。

首页增加模型配置状态、平台登录说明和示例入口，继续招聘区收紧排版。示例仅填入，不自动提交，已有草稿会保留。新注册账号不再自动创建无关示例岗位，历史项目保留。扩展设置明确扩展为可选，并补充安装与连接三步说明。

概览项目区以四张最近项目卡片展示状态、城市、去重后简历数量、当前已分析数量与高匹配数量。当前评分采用项目最近一次完成的分析结果（与候选人页一致），80 分及以上计入“高匹配”，并非录用结论。卡片按实际状态提供查看人选、处理任务或交给助手的入口；不显示没有目标含义的相对进度条。全部项目由右上角入口查看。

本轮桌面交互检查覆盖首次登录弹出、跳过后不重复出现、重新打开、跨页接续、Escape、示例不启动采集、草稿保护、新账号空状态、项目去重人数与 1280/1440/1920 px 布局。

## 模型服务

“设置 → 模型服务”提供 DeepSeek、OpenAI、通义千问、Moonshot、SiliconFlow 和自定义服务预设。用户可以编辑服务地址、模型名与密钥。自定义服务须兼容项目使用的 OpenAI Chat Completions 接口。

密钥保存后输入框清空，已存密钥以掩码提示。切换服务地址时需要提供相应服务的新密钥。“已配置”仅表示配置保存成功，不代表连接测试已经通过。招聘偏好、知识连接、浏览器扩展分面板管理；执行参数留在服务端。

## 动效与性能

参考 [Aceternity 组件库](https://ui.aceternity.com/components) 中的 [Aurora Background](https://ui.aceternity.com/components/aurora-background)、[Tracing Beam](https://ui.aceternity.com/components/tracing-beam)、[Text Generate Effect](https://ui.aceternity.com/components/text-generate-effect)、[Spotlight](https://ui.aceternity.com/components/spotlight) 和 [Moving Border](https://ui.aceternity.com/components/moving-border) 的交互思路。适配为原生 CSS、SVG 与 JavaScript，没有直接引入 React 组件源码。助手首页有流动渐变、需求到人选的追光连线、浮动卡片与核心轨道；输入框呼吸边框、执行波形和推荐卡入场分别响应实际交互。

新增参考 Magnetic Button、3D Card Effect、Card Hover Effect 和 Multi Step Loader 的原生交互：发送按钮内容轻微吸附与掠光，项目/推荐卡指针高光与微倾斜，“开始前”共享滑动背景，页头卡片随指针展开，说明展开淡入。招聘步骤只在服务端阶段变化时播放反馈，当前步骤显示呼吸光环；数量只在实际变化时更新。示例填入和提交成功分别有一次边框脉冲，不生成假进度。

切页没有等待整页动画的延迟；动效局限于局部元素。指针效果共用按需 requestAnimationFrame，触屏不启用；离开视口的装饰和后台页面暂停循环动画。动态插入的项目和推荐卡也会注册交互；尊重 prefers-reduced-motion，实时取消 JavaScript 动画。弹窗支持 Escape、焦点管理和键盘导航，表单提供可访问标签。

## 本次验收

动效补充回归：13 项助手与新手引导相关测试通过；三个工作台脚本通过语法检查。隔离浏览器验证了示例提交、四阶段完成、动态推荐卡注册、说明展开及概览导航，无脚本错误和文档横向溢出。此轮流程使用虚构简历与本地模拟助手。

- 86 项 Python 测试通过，包含后台助手生命周期、用户隔离、失败停止、城市与份数传递、续跑剩余数量、未分析分类与面试反馈流转。
- 助手端到端测试使用本地 HTTP 模型和10份虚构简历，经过真实规划接口、自动采集任务服务、评分服务与推荐结果；同时检查不擅自添加筛选条件。
- 11 个页面地址（含首页与兼容 `/agent`，共10种工作页面）在 1440 px 桌面尺寸检查，并补充 1280 px 与 1920 px 助手页面检查；无脚本异常、无文档级横向溢出。本轮不纳入手机端验收。
- 浏览器交互覆盖项目创建/编辑、简历查看、岗位上下文、搜索草稿、快捷导航、模型配置保存、扩展令牌、候选人约面、报告；本轮重点回归助手提交、重复提交保护、切页恢复、草稿保留与推荐结果。

前端预览使用隔离数据库、虚构简历与本地模拟助手，禁用真实采集和外部模型执行。预览展示2份虚构简历与1份模拟分析，不冒充已找到10份。端到端测试独立验证10份虚构简历的自动调用链；两者均不代表实站访问稳定性、真实模型连接或分析质量已验收。运行中的任务进度采用真实数量；未知完成比例不生成虚假百分比。
